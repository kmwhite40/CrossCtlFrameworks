# Waivers Implementation Plan (CC&E #8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A formally approved waiver stops a finding's operational consequence — alert, task, POA&M — while leaving the finding and its evidence exactly as recorded.

**Architecture:** A new `waivers` table; a pure coverage function over (findings, waivers, today); one insertion point in `record_result` between the evidence flush and `_alert_on_failure`; per-resource attribution via `control_test_resource_results.waiver_id`.

**Tech Stack:** Python 3.12, SQLAlchemy 2 async, pytest + pytest-asyncio. One migration.

**Spec:** `docs/superpowers/specs/2026-09-15-waivers-design.md`

## Global Constraints

- **The §2 invariant.** A waiver never changes `ControlTestResult.status`, the
  `ControlTestResourceResult` rows, `ControlTest.last_status`/`last_tested_at`,
  `effective_verdict`, or the `tested` event. It suppresses exactly the
  `_alert_on_failure` call. A test asserts each of those explicitly.
- **Evidence is persisted before the waiver is consulted.** The check goes
  after the resource rows flush, so no bug in waiver logic can cost a recorded
  observation.
- **Full cover or no suppression.** One uncovered failing resource and the
  alert fires normally.
- **A resource-scoped waiver can never cover a result with no enumerated
  resources** (spec §4 rule 4).
- **`requested` and `revoked` suppress nothing; an expired waiver resumes
  alerting with no action.** Expiry is clock-dependent and gets an injected
  date, never `datetime.now` inside the pure layer.
- **A waiver never closes a POA&M.**
- **`KSIException` is untouched.** No behaviour of `readiness.py` or
  `package.py` changes in this sub-project.
- **RLS:** `waivers` carries `organization_id`, so
  `tests/test_rls_coverage.py`'s `EXPECTED_TENANT_ISOLATION_TABLES` gains it
  and the hardcoded count goes **131 → 132**.
- **Test database is on port 5434.** `CCF_DATABASE_URL=postgresql+asyncpg://ccf:ccf@localhost:5434/ccf_test CCF_DATABASE_URL_SYNC=postgresql+psycopg://ccf:ccf@localhost:5434/ccf_test`. Never run two pytest sessions at once.
- `ruff check src tests` and `mypy src` must be clean; `alembic heads` must show exactly one.

```python
def test_a_whole_check_waiver_covers_every_failing_resource() -> None:
    cov = cover(_findings("fail", "fail"), [_w(None)], today=TODAY)
    assert cov.suppress is True
    assert cov.waived == 2
    assert cov.uncovered == ()


def test_one_uncovered_failing_resource_prevents_suppression() -> None:
    """A partially accepted check is still an unaccepted finding."""
    cov = cover(_findings("fail", "fail"), [_w("res-0")], today=TODAY)
    assert cov.suppress is False
    assert cov.waived == 1
    assert cov.uncovered == ("res-1",)


def test_a_resource_scoped_waiver_cannot_cover_a_resourceless_result() -> None:
    """Spec rule 4. Nothing proves the waived resource was the failing one."""
    cov = cover([], [_w("res-0")], today=TODAY)
    assert cov.suppress is False


def test_a_whole_check_waiver_does_cover_a_resourceless_result() -> None:
    cov = cover([], [_w(None)], today=TODAY)
    assert cov.suppress is True


def test_passing_and_not_applicable_resources_need_no_cover() -> None:
    """Only failing resources have to be covered."""
    cov = cover(_verdicts(("res-0", "fail"), ("res-1", "pass"), ("res-2", "not_applicable")),
                [_w("res-0")], today=TODAY)
    assert cov.suppress is True
    assert cov.waived == 1


def test_manual_review_required_must_be_covered_too() -> None:
    """It is not a clean verdict; leaving it uncovered must keep the alert."""
    cov = cover(_verdicts(("res-0", "fail"), ("res-1", "manual_review_required")),
                [_w("res-0")], today=TODAY)
    assert cov.suppress is False


def test_an_expired_waiver_covers_nothing() -> None:
    cov = cover(_findings("fail"), [_w(None, expires_on=TODAY - timedelta(days=1))], today=TODAY)
    assert cov.suppress is False
    assert cov.waived == 0


def test_a_waiver_expiring_today_is_still_active() -> None:
    """Inclusive: acceptance runs to the end of its last day."""
    cov = cover(_findings("fail"), [_w(None, expires_on=TODAY)], today=TODAY)
    assert cov.suppress is True


def test_a_requested_waiver_covers_nothing() -> None:
    """If asking were enough, anyone could silence a check by asking."""
    cov = cover(_findings("fail"), [_w(None, status="requested")], today=TODAY)
    assert cov.suppress is False


def test_a_revoked_waiver_covers_nothing() -> None:
    cov = cover(_findings("fail"), [_w(None, status="revoked")], today=TODAY)
    assert cov.suppress is False


def test_no_waivers_never_suppresses() -> None:
    assert cover(_findings("fail"), [], today=TODAY).suppress is False


def test_no_failing_resources_does_not_claim_suppression() -> None:
    """An all-passing result is not "suppressed" -- there was nothing to fire.

    Returning suppress=True here would be harmless today but would make the
    flag mean two different things, and the caller only consults it on
    fail/warn.
    """
    cov = cover(_verdicts(("res-0", "pass")), [_w(None)], today=TODAY)
    assert cov.suppress is False
    assert cov.waived == 0


def test_the_narrowest_waiver_is_attributed_to_a_resource() -> None:
    """With both a whole-check and a resource waiver, the resource-specific one
    is recorded for that resource -- the more specific acceptance is the one an
    auditor should see against it."""
    whole, specific = _w(None, id=1), _w("res-0", id=2)
    cov = cover(_findings("fail"), [whole, specific], today=TODAY)
    assert cov.by_resource["res-0"] == 2
```

- [ ] **Step 3: Implement.** In `record_result`, after the `resources` flush
  and before the `if status in ("fail", "warn")` branch:

```python
    # Consulted only after every observation is persisted, so no waiver bug can
    # cost a recorded finding. A waiver suppresses the consequence, never the
    # evidence (see docs/.../2026-09-15-waivers-design.md section 2).
    coverage = None
    if status in ("fail", "warn"):
        active = await waivers_for_test(session, test)
        if active:
            coverage = cover(resources, active, today=datetime.now(UTC).date())
            res.waived = coverage.waived
            for row, finding in zip(resource_rows, resources, strict=True):
                waiver_id = coverage.by_resource.get(finding.resource_id)
                if waiver_id is not None:
                    row.waiver_id = waiver_id
            await session.flush()
```

  then gate the alert:

```python
    if status in ("fail", "warn") and not (coverage and coverage.suppress):
        await _alert_on_failure(session, test, status, detail or "")
    elif status == "pass" and previous_status in ("fail", "warn"):
        await _resolve_on_recovery(session, test, result_id=res.id)
```

  Note the `elif` chain must keep its existing shape: a waived failure takes
  neither branch, and **must not** fall into recovery.
