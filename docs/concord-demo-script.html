Concord — Demo Script

A presenter's walkthrough of the live platform: from cross-framework catalog to guided SSP authoring, config-capture automation, and an enterprise governance program.

Runs at http://localhost:8088 Audience: DIB / federal compliance buyers Format: click-through + a few API calls
Before you start. Bring the stack up with docker compose up -d and confirm /healthz returns ok. Open two tabs: the browser UI (/dashboard) and a terminal for the three API moments. Have /docs ready as the "it's a real, documented API" backstop. The whole arc is about 20 minutes; each step lists a time budget so you can trim to 10 if needed.

The one-liner

Framing (say this first)

Say "Compliance teams in the defense space are stuck between cloud-only GRC tools they can't put CUI into, and spreadsheets that don't scale. Concord is the middle path — a self-hostable, OSCAL-native platform that computes a live SPRS score, authors your SSP, keeps your catalog current, and runs a continuous-monitoring program — all inside your own boundary. Let me show you."
1
2 min

The dashboard & the catalog

Show /dashboard → /controls → /coverage
  • Dashboard: control counts, families, FISMA baselines, last ingestion.
  • Controls: search "session lock", open a control — show objectives + examine/interview/test.
  • Coverage: the family × framework heatmap.
Say "One curated control effort maps across 26 frameworks — roughly 121,000 mappings, full-text searchable. Author once, comply many."

2 min

Live CMMC L2 / SPRS scoring

Show /scoring — toggle a practice's state and watch the SPRS score recompute.
Say "This isn't a stored number in a spreadsheet — it's deterministic and recomputed the instant an implementation changes, so it's defensible to a C3PAO. −203 to 110, transparent math."
3
3 min

Guided SSP authoring + organization-defined parameters new

Show /ssp → create/open a project (platform: AWS GovCloud) → open a control.
  • Point out a Customer Responsibility control: the narrative leads with a [DRAFT] indicator, scoped to the Gov-cloud environment.
  • Fill an ODP field (e.g. incident-reporting timeframe → "within 72 hours to DIBNet").
  • Pick a canned statement from the dropdown, Save — it renders with your parameter substituted.
  • Generate the FedRAMP Appendix-A .docx.
Say "800-171 narratives in minutes, not from a blank page. The blanks are organization-defined parameters pulled from NIST 800-171 — the customer fills them in, and the statement renders complete."

2 min

Config-capture automation new

Show (terminal)
# What the connectors would pull — before any credentials are set
curl -s localhost:8088/api/ssp/connectors | python3 -m json.tool
Say "Two connectors — Microsoft Graph for M365 Government / GCC High, and AWS GovCloud — read live tenant configuration to auto-populate those SSP parameters. Point them at a real tenant with app credentials and the fill-in-the-blanks fill themselves. Until then, they honestly report what they'd map."
5
2 min

Always-current catalogs new

Show (terminal)
# Seed authoritative sources, then check upstream NIST OSCAL for drift
docker compose --profile poller up   # or: ccf sources-seed && ccf sources-check
curl -s localhost:8088/api/catalog/sources | python3 -m json.tool
Say "Your workbook was Rev 1.1. NIST 800-53 is already at Rev 5.2.0. This poller watches the authoritative OSCAL feeds and tells you exactly which controls changed — so your baseline never silently goes stale behind a static spreadsheet."
6
4 min

Governance command center — the enterprise story new

Show /governance
  • Top row: control health %, open tasks, unread alerts, policies · vendors.
  • Click Run ConMon scan — the work queue and alerts populate.
  • Walk the work queue (auto-generated tasks), alerts, and the activity feed.
  • Render a diagram: pick a system → Authorization boundary / Control coverage.
Say "This is what separates a strong internal tool from enterprise GRC. Continuous monitoring scores each control's health from evidence freshness, assessment recency, and open POA&Ms — then opens the work and raises the alerts automatically. Everything emits to an activity feed and to webhooks, so it all talks to each other and to your external systems."
7
2 min

Evidence collection API + artifact store new

Show (terminal)
# An automated collector pushes proof of a control — content-addressed, deduped
echo "MFA enabled for all users" > mfa.txt
curl -s -X POST localhost:8088/api/evidence/collect \
  -F implementation_id=1 -F title="MFA config export" -F kind=config_export \
  -F expires_on=2026-12-31 -F file=@mfa.txt | python3 -m json.tool
Say "Evidence doesn't have to be a human attaching files. Collectors POST here; we SHA-256 and dedupe every artifact, link it to the control, and emit an event. Re-post the same file and it reuses the artifact."

2 min

Documents, OSCAL & reports

Show /reports — export xlsx / docx / csv; then the OSCAL endpoints. 
# OSCAL 1.1 — the government-native, machine-readable package
curl -s localhost:8088/api/oscal/component-definition/1 | head -c 400
Say "SSP, SAR, and reports in the formats an assessor expects — plus OSCAL 1.1 export, right on the FedRAMP 20x / RFC-0024 mandate curve. Nothing here left your boundary."

Close

Leave-behind the product overview PDF, the /docs API reference, and this environment for a hands-on trial.

Appendix

Reset & troubleshooting

  • Bring up docker compose up -d  ·  Logs docker compose logs -f api
  • Seed demo state create an org (/systems), a system, set a control implementation, then Run ConMon scan on /governance.
  • If a page is empty most views are org-scoped — create an organization first, then a system.
  • Scheduled jobs ccf conmon-scan, ccf notify-digest, ccf sources-check (cron-ready).
